FLEET STARTER KIT — SCRIPT AND BLOCK GUIDE
========================================

Scope and safety
----------------
This guide covers every Python and shell script shipped in this repository.
Paths below are relative to starter-kit unless explicitly prefixed otherwise.
Use Python 3.9+ and the standard library; there are no pip dependencies.
The normal runtime target is Linux. Heartbeat/daily metrics use os.getloadavg()
and Linux /proc/meminfo; these are not drop-in native Windows agents.

Public x placeholders (x.x.x.x, xx:xx:xx:xx:xx:xx, x-mesh-host, x-token)
are deliberately non-operational. Replace values only in private ignored
configuration. Role labels such as edge-scout-1 are safe public pseudonyms.
Do not copy real host identities, private evidence or notification topics into
this guide, the repository, prompts or shared screenshots.

"Dry-run" is specific: polling still probes and writes local state; heartbeat
and project monitoring write local JSON. Notification delivery is gated by
--send at callers and by ntfy configuration; Wake-on-LAN requires --apply.
Never execute commands from Markdown, evidence, archives or ingested content.
The project checker uses a fixed local Git inventory command, not input-defined
shell commands. It cannot run tests, models, repairs or external connectors.

Connector documentation:
  ../docs/monitoring-and-protection.md#connectors-and-rave
  ../docs/controller-integration.md
  ../docs/future-integrations.md
  ../docs/ntfy-alerts.md
  README.md and ../README.md#repository-maintenance-conditions

Rave is PLANNED / DISABLED: no verified connector was found. Missing prerequisites:
  Interface: exact product/version, documented local API/CLI/export and schemas,
             read-only operations, transport, timeout and freshness semantics.
  Authentication: method, read-only scopes/account, private credential source,
                  rotation/revocation and certificate/trust requirements.
  Privacy: collected fields, sensitivity, purpose/consent, minimisation/redaction,
           storage/access, retention/deletion and any off-device data flow.
Do not invent an endpoint or mark a connector verified based on its name.
Other gate fields in evidence cover compatibility, verification and approval.

PYTHON RUNTIME SCRIPTS
======================

fleetctl.py — standard-library adopter and owned-file lifecycle
  Public CLI: init, check, connect, deploy, status, uninstall, docs.
    --userconfig PATH loads private JSON; explicit flags override saved values.
    Names: --kit-name, --unit-prefix (default fleet), --hub-label,
    --client-label, --node-name; --role hub|client selects units.
    Paths/target: --install-dir, --repo, --host x-user@x-host, --source.
    Approval: deploy --apply; --enable explicitly requests timer activation;
    --send permits poll/daily notifications; uninstall --apply permits removal.
    --include-config may repeat only fleet.env, fleet_manifest.json,
    maintenance.json. Config transfer is off by default.
    Explicit trust: --trust-host-key --expected-fingerprint SHA256:...;
    supply an independently verified fingerprint, never a guessed/scanned trust.
    init --output PATH creates a private config exclusively.
  Inputs: selected settings, exact public runtime source whitelist, optional
          approved private config; target home/UID, systemd user session,
          SSH known-hosts or explicitly approved out-of-band fingerprint.
  Outputs: private settings JSON, source SHA256 manifest, generated unit files,
           .fleetctl-installed.json ownership/hash record, per-file status
           (unchanged/modified/missing/unsafe), refusal diagnostics and success/
           nonzero status (ordinary refusal 1; argparse usage errors may be 2).
  Blocks:
    - settings/name/path validation: strict lowercase bounded labels; hub/client
      role; no root SSH target, unsafe path components or unknown config keys.
    - inspect/home_path/read_private: reject symlinks, unsafe ancestors,
      foreign ownership and overly accessible private files; destination stays
      strictly below the acting user's home.
    - environment/validate_runtime: parse env/JSON as data, reject placeholders
      and shell expressions; require client node choice and activation inputs.
    - bundle/digest: select fixed allowed files, add only explicitly approved
      private filenames and compute SHA256; no recursive private-tree copying.
    - units/install: generate destination/prefix/role-aware units, preflight
      ownership and existing hashes before writes, write restrictive files and
      record ownership, reload user daemon; default units stay disabled.
    - trusted/ssh_options/connection: fixed unprivileged remote Python probe;
      BatchMode=yes, StrictHostKeyChecking=yes, ForwardAgent=no; password and
      keyboard-interactive authentication disabled. Unknown keys halt.
      Explicit fingerprint trust uses a private per-operation known-hosts file,
      independently checked with ssh-keygen, removed after the operation.
    - deploy/receive: print exact manifest before approval; applied SSH staging
      transfers exact files and request data, verifies whitelist/checksums before
      installation, and cleans successful staging. Failed private stages can
      remain for operator inspection; no recursive cleanup is executed.
    - installed/local_status: restrict manifest paths to allowed managed entries;
      inspect bytes; uninstall only within recorded ownership boundaries.
    - main/parser: public command routing; _install is the legacy wrapper
      implementation detail and _receive is the verified deployment receiver,
      not interfaces to invoke manually or approval bypasses.
  Side effects by command:
    init writes one mode-0600 JSON; check only reads local config;
    connect contacts SSH and runs the fixed home/UID probe;
    deploy without --apply only reads/hashes/prints, no network/write/services;
    deploy --apply stages/transfers/installs and reloads systemd --user;
    status reads managed-file state (over SSH when a host is selected);
    uninstall is a read-only plan until --apply, then removes eligible owned
    files and reloads units. Explicit host-key trust temporarily writes private
    trust data. No root/sudo, passwords, agent forwarding or linger changes.
  Prerequisites: Python 3.9+, trusted reviewed source, acting-user ownership,
    private config (0600) and directories (0700), systemd user session for
    installation. Remote use needs OpenSSH ssh/scp; explicit fingerprint trust
    also needs ssh-keyscan/ssh-keygen, independent trusted fingerprint evidence,
    remote Python and user systemd.
  Limits: checksum integrity is not source authenticity. No backup, automatic
    upgrades/merges, heartbeat transport, controller/Rave connector, live WoL,
    AI dispatch or unattended deployment. Status is file integrity, not live
    health/lifecycle evidence. Preserve original settings for uninstall and
    separately review retained private/modified data; never recursively delete.
  Links: README.md#safe-adopter-workflow;
         ../docs/monitoring-and-protection.md#adopter-threat-model.

src/docs_publish.py — private Markdown staging, re-scan and local knowledge index
  CLI (via fleetctl wrapper): python3 fleetctl.py docs <stage|apply|check|audit|index> --config /abs/private/docs-config.json [--reviewed]
  Inputs: owner-only private publish config and redaction map outside the public
          checkout; explicit source→target Markdown mapping; private/public roots
          and local stage directory.
  Outputs: staged rendered Markdown, review.diff, manifest.json, vetted.json,
           audit.json and knowledge-index.json under the private stage path;
           nonzero exit on any privacy/review/permission failure.
  Blocks:
    - load/secure: enforce owner-only files and secure directories, reject
      symlinks/overlaps/publicly tracked config paths and unsafe mappings.
    - render/scan: remove private blocks, apply public-only replacements,
      reject malformed markers, mask known identifiers and scan for surviving
      private terms/patterns without echoing matched values.
    - stage: render mapped files into a fresh review directory, record baseline
      hashes and sanitised diff for human approval; never writes public files.
    - apply (--reviewed required): re-render and re-scan, verify staged and
      baseline consistency, refuse drift, replace mapped public files atomically,
      re-audit resulting public tree, then write vetted evidence.
    - audit/check: scan current public Markdown and evaluate vetted freshness/
      full coverage; prior approval never bypasses re-scan.
    - index: generate a local two-tier document index (private/public metadata,
      title/hash/mtime/tier, knowledge_only=true). This is data only.
  Side effects: local file reads/writes only. No network, no command execution
                from Markdown and no model invocation/publishing.
  Prerequisites: private workflow and permissions prepared outside the public
                 repository; reviewed redaction map and explicit document mapping.
  Limits: pattern scans cannot guarantee zero leakage or prevent inference.
          Human review remains mandatory before public publishing.
  Links: ../docs/private-public-docs.md; ../docs/workflow.md.

src/resolver.py — imported identity-first resolver; no standalone CLI
  Inputs: manifest JSON, local neighbour output, optional Tailscale JSON,
          injected probe callable and per-node MAC/name/address fields.
  Outputs: validated manifest, maps of observations, Resolution(address, channel)
           or None when no candidate responds.
  Blocks:
    - validate_address: reject malformed/non-operational x addresses/hostnames
      before DNS lookup or network access; retain valid loopback/protocol use.
    - normalize_mac / parse_neighbor_table: canonicalise hardware identities;
      ignore FAILED and INCOMPLETE neighbour entries.
    - read_neighbors: fixed "ip neigh show" command when ip is installed.
    - read_mesh_peers: fixed "tailscale status --json", online peers only;
      missing CLI yields an empty map. Installed LAN/mesh discovery commands
      that fail raise visible errors rather than silently implying no peers.
    - load_manifest: read and validate the inventory and required node fields.
    - resolve: try live LAN-by-MAC, online mesh-by-name, last-known address;
      use the caller's probe before accepting a candidate.
  Side effects: read-only local subprocesses; the injected probe may open TCP
                connections. It does not configure the mesh or dispatch work.
  Prerequisites: valid private manifest; iproute2 for LAN lookup, optional
                 authenticated Tailscale CLI for mesh lookup.
  Limits: address selection is not cryptographic host authentication or the
          broader controller/adoption/conflict workflow.
  Links: ../docs/polling.md; ../docs/mesh-and-updates.md.

src/fleet_poll.py — fleet reachability and notification transitions
  CLI: python3 src/fleet_poll.py --manifest config/fleet_manifest.json
       Optional --state PATH; --send permits ntfy delivery.
  Inputs: validated manifest, previous fleet state, neighbour/mesh observations,
          configured TCP port (default SSH port 22), optional heartbeat files.
  Outputs: state/fleet_status.json by default; per-node role, up/channel,
           transition/reminder state, heartbeat stale flag and checked_at epoch.
           Prints poll counts and dry-run alerts unless --send is used.
  Blocks:
    - tcp_probe: short TCP connection attempt; failure means unreachable.
    - load_state / save_state: read previous JSON; write via sibling .tmp
      and replace the state file.
    - heartbeat_age_minutes: read NAME.json epoch from heartbeat_dir.
    - poll_once: resolve/probe nodes; seed first reachability state, alert on
      up/down transitions, remind after 24 hours down, flag a known stale
      heartbeat. If heartbeat_dir is configured, missing/invalid/old heartbeat
      is stale for a reachable node and can alert even on a first observation.
    - main: parse arguments, collect observations, optionally notify, save state.
  Side effects: read-only local CLI queries, TCP probes, local state writes;
                outbound HTTPS/spool writes only through notifier when sending.
  Prerequisites: edited inventory and access to configured ports; optional
                 collected heartbeat files and private ntfy settings.
  Limits: a listening TCP port is not verified device identity/service health;
          heartbeat collection is not included. Missing/invalid heartbeat files
          are stale when heartbeat_dir is configured, not evidence of health.
  Unit: fleet-poll.timer every two minutes when manually enabled.

src/heartbeat.py — local health sample for hub collection
  CLI: python3 src/heartbeat.py --name edge-scout-1
           --out state/heartbeats/edge-scout-1.json
  Inputs: role-name argument, current clock, root filesystem usage, load,
          CPU count and /proc/meminfo where available.
  Outputs: name/epoch/load1/cores/mem_pct/disk_pct/disk_free_gb JSON.
  Blocks:
    - collect: read local metrics; unavailable memory metric stays null.
    - main: require name/out, create parent directories, write sibling .tmp
      and replace destination.
  Side effects: local filesystem reads and output writes only; no upload.
  Prerequisites: Linux/Unix load support, writable output path. Arrange hub
                 collection separately with an approved transfer mechanism.
  Unit: fleet-heartbeat.timer every five minutes; edit name/out before enabling.

src/ntfy_notify.py — shared formatter, publisher and bounded retry spool
  CLI: python3 src/ntfy_notify.py (one delivery test).
  Inputs: NTFY_TOPIC, NTFY_SERVER, optional NTFY_TOKEN, SITE_NAME,
          FLEET_ENV (default ./config/fleet.env), NTFY_DRY_RUN and NTFY_SPOOL.
          Environment settings override file values; empty topic is dry-run.
  Outputs: formatted payloads; dry-run stdout or outbound JSON publish;
           boolean delivery result, test CLI exits 0/1.
  Blocks:
    - settings/style table: load settings and select emoji/tags/priorities.
    - bullets / fields / section / bar / compose: common report formatting;
      footer includes site, real local hostname and timestamp. Redact before sharing.
    - truncate / build_payload: UTF-8-safe capped body and JSON payload.
    - validate_delivery: reject placeholder endpoint/topic/token and invalid
      endpoint scheme, embedded credentials or port before opening the network.
    - _post: validate every payload, including queued retries, immediately before
      outbound HTTP(S) publishing with optional token. A spool entry cannot
      bypass endpoint/topic/token placeholder checks.
    - _spool / flush_spool: keep failed payloads, resend on next real send;
      retain at most 200 messages. Disk failures can still lose messages.
      Corrupt or invalid queued entries stay in the private spool and produce
      only a generic warning; payload and exception text are never printed.
    - send: print only if NTFY_DRY_RUN=1 or topic is empty; otherwise flush
      only after current delivery settings/payload validate. Attempt delivery
      at delays 0, 2 and 6 seconds, then spool.
  Side effects: network publishing, spool reads/writes/deletion; running the
                CLI can send immediately when a real topic is configured.
  Prerequisites: an approved server/topic and outbound access for actual delivery.
                 Prefer authenticated self-hosting; topic names are sensitive.
                 Set NTFY_SPOOL to a private writable project-local path for
                 environments where the code's system spool default is unsuitable.
  Limits: best-effort bounded spool, not guaranteed delivery or an approval API.
  Link: ../docs/ntfy-alerts.md.

src/wol_healer.py — opt-in Wake-on-LAN packet sender
  CLI: python3 src/wol_healer.py --manifest config/fleet_manifest.json
       Optional --state PATH, --broadcast ADDRESS, --apply.
  Inputs: manifest, prior fleet state and an explicitly reviewed LAN broadcast.
  Outputs: printed candidates/events; applied events may send an ntfy summary.
  Blocks:
    - magic_packet: validate/encode one MAC into a 102-byte magic packet.
    - send_magic: UDP broadcast on protocol port 9.
    - candidates: only wake_required nodes with MACs and up=false in state.
    - main: print intent by default; send packets only with --apply; notify
      after applied events through the shared publisher.
  Side effects: default reads/prints only; --apply emits LAN packets and may
                publish/spool notifications. It does not confirm wake success.
  Prerequisites: reviewed real MAC/broadcast, authorised wake flag, capable
                 hardware and a suitable local broadcast domain.
  Limits: no recovery verification, relay, controller repair or cooldown loop
          is implemented by this script.
  Unit: fleet-heal.timer every five minutes, service is dry-run until edited.

src/project_monitor.py — read-only local repository/evidence assessment
  CLI: python3 src/project_monitor.py --repo PATH
       Optional --config PATH, --evidence PATH, --out PATH.
  Inputs: Git checkout; config/maintenance.example.json by default;
          state/maintenance_evidence.json by default; current epoch clock.
  Outputs: state/project_status.json by default; health and findings, check
           outcomes, Markdown review needs and connector lifecycle/gate state.
           Exit 0 only for healthy; attention/invalid exits nonzero.
  Blocks:
    - read_json / fresh: binary JSON-object reads capped at 1 MiB of real bytes,
      and finite numeric epoch validation; stale, future or non-numeric
      timestamps cannot pass.
    - snapshot: fixed "git ls-files" command inventories tracked and non-ignored
      new files; hash paths/content for revision and every Markdown file for review.
      Sorted unique --cached/--others/--exclude-standard results include unstaged
      additions: new code invalidates revision; new Markdown also needs review.
      Ignored runtime state/config do not participate.
      Unsafe symlinks/paths or unreadable files cannot establish healthy evidence.
    - evaluate: compare configured required_checks with evidence statuses,
      timestamps and revision; compare reviewed docs hashes; assess configured
      connector implementation/lifecycle and six prerequisite gates.
    - run: collect local inputs; missing/invalid data becomes an invalid result,
      without echoing arbitrary source content.
    - summary: validate derived status for daily reporting, including freshness,
      expiry, required successes, documentation needs and connector gates.
      Historical passed timestamps remain last_successful_check and are marked
      stale when old; they do not override current failed/outdated checks.
    - main: parse paths, assess, atomically replace output and set exit status.
  Side effects: read-only local Git invocation and file reads, then output
                directory/.tmp/status writes. No network calls or input commands.
  Prerequisites: Git, checkout access, reviewed documentation hashes, genuine
                 current evidence and the configured required checks.
                 An ignored config/maintenance.json private copy is optional;
                 --config must select it explicitly (including in the unit).
                 Default remains config/maintenance.example.json.
  Limits: it does not itself execute tests or generate evidence. Rave is
          blocked from implemented/verified status; planned connectors remain
          attention, not evidence of an operational integration.
          Sorted summary connector-1 is ntfy, connector-2 is Rave under the
          example policy. Rave planned means exit 1 and no daily ALL GREEN.
  Evidence authoring: deliberately import snapshot(repo) to obtain the current
          fingerprint and candidate Markdown hashes. Review each document
          before manually approving its hash in evidence.docs. Run existing
          reviewed checks separately, record actual status/epoch/fingerprint,
          and fill six connector gates from real observations, not guesses.
          Re-snapshot after changes; never auto-approve candidate hashes.
  Unit: optional hourly fleet-project.timer; edit --repo %h/xxxx-project to the
        reviewed checkout before activation. Default/legacy installation leaves
        it disabled; explicit adopter --apply --enable may activate it with --repo.
        Periodic hashing/reassessment happens only if enabled; it never reruns
        tests, approves documentation or refreshes underlying evidence timestamps.
        Daily 07:10 and hourly calendar schedules use the host local timezone.
        Inspect systemctl --user status/list-timers and journalctl --user locally;
        an expected ATTENTION exit 1 appears as a failed oneshot, not green.
  Full schema/limits: ../docs/monitoring-and-protection.md#local-project-maintenance

src/daily_status.py — combine hub metrics, fleet state and project status
  CLI: python3 src/daily_status.py
       Optional --state PATH, --manifest PATH, --project-state PATH, --send.
  Inputs: local host metrics, fleet snapshot, expected inventory, project status.
  Outputs: daily headline/body on stdout; --send publishes through ntfy.
           Exit 1 for attention or failed delivery, 0 for healthy delivery/print.
  Blocks:
    - host_metrics: kernel/load/memory/root-disk metrics; disk warning at 90%.
    - build_report: combine host warnings, down/stale fleet entries, fleet
      evidence validity/freshness and project summary into green/ATTENTION.
    - main: read/validate local state and expected manifest, compare coverage,
      read project summary, then print or send at attention-aware priority.
  Side effects: local reads; --send may publish and write/flush notification spool.
  Prerequisites: Linux metric support and fresh, valid expected fleet/project
                 observations. Fleet checked_at, not state-file mtime, gives age.
  Limits: missing/empty/partial/stale state is not proof of health. It does
          not collect external evidence, inspect the ntfy backlog, read vault
          capacity, run AI analysis or inspect every systemd job.
  Unit: fleet-daily.timer at 07:10 local time when manually enabled.

PYTHON TEST SCRIPTS
===================

Run existing tests with: python3 -m unittest discover -s tests
These are validation tools, not operational collectors or deployment evidence
unless their actual result/time/revision is separately reviewed and recorded.
They use unittest/mock from the standard library. Do not replace their fixtures
with real credentials or fleet addresses.
The existing src-runtime test suites use TEST_DIR = Path(tempfile.gettempdir()), normally
/tmp on Linux, not the repository's tests directory; TemporaryDirectory handles
cleanup. "Test-local" below means scoped to the test, not stored beside its source.

tests/test_fleetctl.py
  Blocks: FleetctlTests exercise settings/init, manifest dry-run, unsafe inputs,
          private permissions/symlinks, staged SSH/scp deployment, trust checks,
          tamper rejection, ownership/idempotence, activation and uninstall.
  Inputs: synthetic source/home/config fixtures and standard-library mocks;
          command stubs simulate ssh/scp/systemctl/key tools.
  Outputs: unittest result stream and stub command logs.
  Side effects: disposable checkout-local .fleetctl-test-* fixture directories
                and local stub subprocesses, cleaned through TemporaryDirectory;
                no live SSH, notification delivery or systemd management.
  Limits: stubbed success is not evidence of a real SSH/systemd deployment.

tests/test_kit.py
  Blocks: ResolverTests (MAC/neighbor/trust order), PollTests (seed, transitions,
          reminders, heartbeat age), NtfyTests (format/truncation/dry-run network
          suppression), OtherTests (magic packets, wake filtering, daily warnings).
  Inputs: synthetic fixtures, injected probes and current host metrics in one case.
  Outputs: unittest result stream.
  Side effects: test-local scratch heartbeat files and in-memory state;
                NTFY_DRY_RUN=1 prevents real notification delivery.

tests/test_daily_status.py
  Blocks: DailyReportTests (freshness/coverage/project attention and report
          behaviour), DailyCliTests (state/manifest/project input handling).
  Inputs: synthetic timestamps/state/metrics and mocked notification calls.
  Outputs: unittest result stream.
  Side effects: test-local scratch files; mocks avoid fleet/notification traffic.

tests/test_project_monitor.py
  Blocks: ProjectMonitorTests exercise config/evidence validation, check
          freshness/revision, Markdown drift, connector gates, snapshot,
          invalid inputs, summary and CLI exit/output handling.
  Inputs: synthetic local configs/evidence, small test checkouts, patched clocks.
  Outputs: unittest result stream and local output fixtures.
  Side effects: test-local scratch files/checkouts, fixed local Git operations;
                no live connector or ingested command execution.

tests/test_runtime_validation.py
  Blocks: ResolverValidationTests (manifest/address/MAC rejection and safe
          runtime input handling), NtfyValidationTests (safe setting/delivery
          handling and notification boundaries).
  Inputs: synthetic identifiers and malformed values, mocked network/process calls.
  Outputs: unittest result stream.
  Side effects: test-local scratch files and mocked operations, not live probes.

SHELL SCRIPTS
==============

install.sh — compatible local wrapper; never enables timers
  Inputs: first role argument (hub default, client for heartbeat-only), remaining
          fleetctl options, HOME and source directory. Client requires an
          explicitly chosen --node-name (x-node is non-operational).
  Outputs: fleetctl's local installation and ownership record; initial private
           config from examples only when absent; units NOT enabled.
  Blocks: strict Bash mode; locate script directory; take/shift role; exec
          Python fleetctl.py _install with --role, --send and forwarded flags.
  Side effects: shared installer writes exact allowed files and generated user
                units, creates private config/directories and reloads systemd;
                never enables timers. --send prepares legacy notification
                behaviour for a later separately approved manual activation.
  Prerequisites: Bash, Python 3.9+, systemd user session, user-owned HOME and
                 reviewed source/config; same collision/permissions checks as
                 adopter deployment. No dependencies are installed.
  Limits: --enable is refused, not forwarded as an activation bypass. Matching
          managed bytes may be reused; unowned/changed target content is not
          overwritten. Client heartbeat collection remains manual.

build_package.sh — build a distributable archive of public kit content
  CLI: ./build_package.sh
  Inputs: fleetctl.PUBLIC's exact runtime whitelist, plus the shipped
          README/prompt/checklist/TXT guide, six explicitly named test files
          and the five named systemd service/timer template pairs.
          No runtime state, actual config or arbitrary directory/glob content.
  Outputs: starter-kit/fleet-kit.zip, replacing any archive of that name.
  Blocks: strict shell mode; cd to script directory; inline standard-library
          Python imports fleetctl's fixed whitelist, validates selected files,
          rejects a symlink output, writes the zip and prints its output path.
  Side effects: replaces the local zip; Python may create its import cache;
                does not install, contact a host or enable services.
  Prerequisites: Bash, Python 3.9+, readable shipped files and writable kit folder;
                 no external zip command or Python dependency is required.
  Limits: a checksum/deployment manifest is generated by fleetctl deploy, not
          an authenticity signature for this zip. Review the source/provenance.
          The archive is not the full reviewed repository or a deployment
          attestation; it excludes private settings, evidence and archives.

MAINTENANCE REMINDER
====================
After any script change, compare this inventory and block descriptions with the
actual source. Update schema/CLI/timer examples together. Follow the root
../README.md#repository-maintenance-conditions and the local maintenance contract
at ../docs/monitoring-and-protection.md#local-project-maintenance; approve
documentation SHA256 only after review. Re-scan staged/current public Markdown
for each publish cycle, including previously approved files. If privacy checks
fail, correct source/map and re-stage before updating public docs.
